GitHub how-to

The clicks for putting your project on GitHub. Why the repo is public with the MIT licence, and what goes in your README: see Build.

Make an account (5 minutes)

Sign up free at github.com/signup and confirm your email. Then sign in on the laptop you will bring.

Create the repo (2 minutes)

  1. On github.com, click New repository.
  2. Name it after your project. Choose Public.
  3. Tick Add a README file. Under Choose a license, pick MIT License.
  4. Click Create repository. Share the link with your team.

Check: the repo page shows Public next to its name and MIT license on the right.

Forgot one? To make it public: Settings, then Change visibility (in the red Danger Zone box). To add the licence: Add file, Create new file, name it LICENSE, click Choose a license template, pick MIT License, then Commit changes.

Invite your team: Settings, Collaborators, Add people; they accept the email invite. Teammates without a GitHub account can still view and download from a public repo.

What goes in, what stays out

UploadKeep out
Your code (for example app.py) and any scripts.env, API keys, tokens, passwords, .streamlit/secrets.toml
requirements.txtData exported from Snowflake Marketplace
README.md and LICENSEFiles over 25 MB: link to the source instead
Your notes and queries (for example in a docs folder), with account names removed.venv/, venv/, __pycache__/, .DS_Store, notebook checkpoints
Small open-licence data you are allowed to share, with its source namedRaw AI chat or session logs that may contain account names

Why these stay out: see Build.

.gitignore: create a file named .gitignore in your project folder at the start, with these lines:

# secrets
.env
*.env
.streamlit/secrets.toml
# data you may not publish: name each Snowflake Marketplace export
# data/my_marketplace_export.csv
# Python and tools
.venv/
venv/
__pycache__/
*.pyc
.ipynb_checkpoints/
.DS_Store

Keep keys in .env from the first minute, and they stay out automatically. Name each Snowflake Marketplace export in .gitignore, as the worked example does. Open data you may share goes up with your code.

Add your files: pick one way

A. In the browser (no tools needed). In the repo, click Add file, then Upload files, drag in only the files in the Upload column above, and click Commit changes. Never drag the whole project folder: the browser upload ignores .gitignore and would take .env and your Marketplace exports with it.

B. Ask your AI tool. If your builder already pushes to GitHub from your AI tool: first ask it to "show me every file that will be committed" and check none is in the Keep out column; then ask it to push to your repo link. Otherwise use A.

After every upload: open the repo page and look at the file list. No .env, no Marketplace data, no key.

GitHub for non-coders

You only need three things.

  • See the files: open the repo link your team shares.
  • Download: everything at once with the green Code button, then Download ZIP; one file by opening it and clicking the download icon. Download again when you need the latest version; do not edit an old copy.
  • Add or update a file (needs a GitHub account and an invite): open the folder you want, click Add file, then Upload files, then Commit changes. Or open a text file and click the pencil to edit it.

Who edits what: see the team tips on Build.

The README

Edit README.md in the repo: open it and click the pencil icon. What goes in it: see Build.

If a key gets uploaded by mistake

Delete the key at its source straight away (for Gemma: Google AI Studio, API keys) and make a new one. Deleting the file from GitHub is not enough: the old version stays in the repo's history.
